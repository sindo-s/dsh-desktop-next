# 单窗口聊天（0.4.0-alpha.3）

顶部“聊天 / 桌面管理”切换的是同一原生窗口中的页面。官方工作台使用独立子 WebView，管理页仍使用本地页面。
不是 iframe，不放宽官方 frame/CSP 策略，也不修改官方前端。切回管理页只隐藏聊天视图；再次进入相同内核运行地址时复用它，保留当前输入和页面状态。
重启内核导致地址变化时会重新加载工作台；此时页面草稿不承诺保留。

聊天视图占据顶部 56 个逻辑像素以下的区域，随窗口大小和 DPI 调整。顶部导航始终由本地管理页渲染。
只允许工作台在当前 loopback origin 内导航，不允许工作台创建额外弹窗。

## 权限边界

Tauri capability 从 windows: main 改为 webviews: main，避免同窗口的 core 子视图继承管理权限。
所有宿主命令使用调用 Webview 身份检查，不使用父窗口身份检查。core 与 main 共享窗口，但不共享原生权限。
管理页面不暴露通用脚本执行能力，远程工作台也不获取目录选择、更新、安装等权限。

Tauri 2.11.5 的多 WebView 接口仍位于 unstable feature 下，因此固定 Tauri 精确版本；后续升级该依赖时需重新做原生回归测试。
官方内核仍独立更新，不依赖这个桌面依赖版本。

## 回归验证

scripts/verify-desktop.mjs 检查只有 main 一个原生窗口、core 属于 main、切换不重载聊天、切回管理页仍可调用管理命令、远程原生命令拒绝，以及两个窗口尺寸下聊天区域宽高。
scripts/resize-test-window.ps1 仅用于测试：按测试进程 ID 调整本应用窗口，不会移动或调整其他应用。

2026-09-08：19 项 Node 测试、3 项界面测试和 3 项 Rust 测试通过。原生验证确认 main/core 都属于 main 窗口、聊天页面状态保留、两个窗口尺寸布局正确，管理命令仍可调用而聊天页原生命令被拒绝。
